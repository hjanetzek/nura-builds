# Upstream candidates

Fixes in this repository's recipes (patches in `aports/`, or `sed` in a recipe's `prepare()`) that
belong in the upstream projects, and upstream bugs noticed but not fixed here. Changes to zynthian
itself are logged in zynthian-ui's
[docs/upstream-candidates.md](https://github.com/hjanetzek/zynthian-ui/blob/main/docs/upstream-candidates.md).
Keep it up to date with each fix: add a row when a recipe works around an upstream problem.

Status: **ready** (a patch file, can be sent as is), **sed** (a `sed` in the recipe: needs a proper
patch), **open** (noticed, not fixed), **proposed** (sent upstream, with the link), **merged**.

Patches taken from Debian or Alpine (sooperlooper, eq10q, Qt) are not listed.

## Bugs (on every platform)

| Project | Status | Where | Problem and fix |
|---|---|---|---|
| [LinuxSampler](https://www.linuxsampler.org/) 2.5.0 | ready | `aports/engines/linuxsampler/thread-stop-joined.patch` | **`Thread::StopThread()` detaches a joined thread.** After `pthread_join()` the state is still `PENDING_JOIN` (set by the thread's destructor), so `pthread_detach()` follows on the joined thread: undefined behaviour, glibc returns an error, musl uses freed memory and segfaults. Crashes linuxsampler on every `RESET CHANNEL` of a channel with an SFZ instrument (zynthian removing a chain). Fix: `state = NOT_RUNNING` after the join. |
| [LinuxSampler](https://www.linuxsampler.org/) 2.5.0 | ready | `aports/engines/linuxsampler/thread-sched-self.patch` | **A new thread sets its scheduling through `__thread_id` before it is set.** `SetSchedulingPriority()` runs in the new thread (`pthreadLauncher`) and uses `__thread_id`, which `pthread_create()` may store only after the thread started (musl does): `pthread_setschedparam(0, ...)`, segfault at times at `LOAD ENGINE`. Fix: `pthread_self()`. |
| [LinuxSampler](https://www.linuxsampler.org/) 2.5.0 | ready | `aports/engines/linuxsampler/jack-port-rename.patch` | **JACK output ports renamed with the deprecated `jack_port_set_name()`.** PipeWire's JACK library returns success without renaming ("deprecated"), so `SET AUDIO_OUTPUT_CHANNEL_PARAMETER ... NAME=` has no effect and the ports stay `0`, `1`, ...: zynthian, which names them `out<N>_l/_r` and routes the chains by those names, leaves LinuxSampler's audio unconnected. Fix: `jack_port_rename(client, port, name)` (jack2 and PipeWire). Not yet verified on a device. |
| [MOD Arpeggiator](https://github.com/mod-audio/mod-arpeggiator-lv2) | ready | `aports/lv2/mod-arpeggiator-lv2/midibuffer-by-reference.patch` | **150 KB copied onto the audio thread's stack.** `run()` takes the MIDI buffer by value; with musl's 128 KB default thread stack the host's audio thread overflows (segfault on the first `run()`). Fix: `getMidiBuffer()` returns a const reference. |
| [Monique](https://github.com/surge-synthesizer/monique-monosynth) | ready | `aports/lv2/monique-lv2/headless-no-display.patch` | **Crash without an X display.** The editor code dereferences the host display (`get_host_display()`, null without X); JUCE's LV2 helper creates the editor at build time, so headless builds (CI) die in the plugin's crash handler (SIGKILL). |
| [Vaporizer2](https://github.com/VASTDynamics/Vaporizer2) | sed | `aports/lv2/vaporizer2-lv2/APKBUILD` | **Unchecked `std::optional` dereference.** `processBlock()` does `*getPlayHead()->getPosition()`, empty in hosts that send no time info yet (jalv): abort with `_GLIBCXX_ASSERTIONS`, undefined behaviour without. Fix: keep the `Optional`, its `orFallback()` calls follow. |
| [Regrader](https://github.com/linuxmao-org/regrader-port) | sed | `aports/lv2/regrader-lv2/APKBUILD` | **A macro named `maybe_unused`** (`global.h`) breaks `[[maybe_unused]]` in GCC 15's libstdc++ headers. Fix: rename the macro. |
| [TalentedHack](https://github.com/jeremysalwen/TalentedHack) | sed | `aports/lv2/talentedhack-lv2/APKBUILD` | **C99 `inline` without an external definition** (`midi.c`, `talentedhack.c`, `quantizer.h`): unresolved symbols at `-O0`/`-Os`, multiple definitions with `-fgnu89-inline`. Fix: `static inline`. |
| [plugdata](https://github.com/plugdata-team/plugdata) develop (2026-11-03) | ready | `aports/lv2/plugdata/keyboard-layout-eof.patch` | **`OSUtils::getKeyboardLayout()` (Linux) never ends.** It reads `setxkbmap -print` in `while (1) { getline(...); ... }` with no end at EOF (and `strstr` on a NULL line if the first read fails). glibc's `popen()` refuses the mode `"rb"`, so the function returns QWERTY before the loop; musl's accepts it, and the editor's constructor hangs (JUCE's LV2 helper creates the editor at build time: the build hung). Fix: mode `"r"`, `while (getline(...) != -1)`. |
| [Aeolus](https://github.com/zynthian/aeolus) (zynthian's fork) | ready | `aports/engines/aeolus/mlock-memlock-limit.patch` | **`mlockall(MCL_CURRENT \| MCL_FUTURE)` under a memlock limit.** As a normal user (8 MB limit) the call succeeds, and later mappings fail once the limit is reached: libpipewire's shared memory, then a crash in its protocol thread while connecting. ZynthianOS runs it as root (no limit). Fix: lock only when `RLIMIT_MEMLOCK` is unlimited. |
| [DISTRHO-Ports](https://github.com/DISTRHO/DISTRHO-Ports) (DISTRHO's JUCE 5), [Helm](https://github.com/mtytel/helm) (its JUCE copy) | ready | `aports/lv2/distrho-ports-lv2/juce5-lv2-message-thread-exit.patch`, `aports/lv2/helm-lv2/juce-lv2-message-thread-exit.patch` | **SIGSEGV in the last instance's cleanup (OB-Xd, TAL-*, Helm; 17 per factory snapshot run on the Pi 4).** The LV2 wrapper's `~SharedMessageThread` calls `stopDispatchLoop()`; `InternalMessageQueue::postMessage()` writes the wake-up byte with its lock released and relocks it after. The message thread dispatches the quit message meanwhile, leaves `run()`, and its `ScopedJuceInitialiser_GUI` shuts JUCE down and deletes the queue: the relock hits freed memory (musl unmaps it: SEGV_MAPERR; more likely on one CPU). Fix: `run()` waits on a `WaitableEvent` the destructor signals after posting. Qt VM, parallel stops on one CPU: OB-Xd 50/80 → 0/48, TAL-Filter 11/12 → 0/24 (Helm not rebuilt). |
| [zynthian's jalv](https://github.com/zynthian/jalv) (asyncli) | ready | `aports/zynthian-jalv/exit-fixes.patch` (fork branch `exit-fixes`) | **Crash at exit after a command.** The command line thread isn't stopped: a `preset` still loading when SIGTERM arrives reads into the world `jalv_close()` frees (SIGSEGV in sord, VM 40/40 → 0/40). `jalv_close()` also stopped the worker before deactivating JACK. Fix: a lock around each command that main() takes before `jalv_close()`; JACK deactivated first. On musl `exit()` also waits for the command thread's `fgets()` on stdin (zynthian closes it). |
| [jalv](https://github.com/zynthian/jalv) (zynthian's fork, asyncli) | ready | `aports/zynthian-jalv/bundle-list.patch` | **Every jalv loads the whole LV2 world.** `lilv_world_load_all()` parses every manifest on LV2_PATH (~550 bundles, ~4,200 presets on a zynthian): ~0.9 s of a jalv start on a Pi 4, for every plugin of a snapshot. Fix: option `-B DIRS` (bundle directories, `:`-separated) loads only these bundles plus the specifications among them; if the plugin isn't there, jalv loads everything as before. zynthian-ui passes each plugin's bundles from its own lilv world (branch `fast-load`, `zynthian_lv2.get_plugin_bundles()`). Branch `bundle-list` in the jalv fork. |
| [zynthian's jalv](https://github.com/zynthian/jalv) (asyncli) | ready | `aports/zynthian-jalv/bundle-list.patch` (fork branch `bundle-list`, 2nd commit) | **`-B` missing in the GTK frontend.** jalv.gtk3 parses options with GOption (`jalv_gtk.c`), not the console parser: `-B/--bundles` added to its table (same `opts.bundles`). VM: Helm in `jalv.gtk3 -H` starts in 0.30 instead of 0.43-0.58 s. |
| [zynthian's jalv](https://github.com/zynthian/jalv) (asyncli) | ready | `aports/zynthian-jalv/fast-exit.patch` (fork branch `fast-exit`) | **Slow exit after SIGTERM.** The first `preset` command parses the plugin's whole preset file (Helm 4.7 MB, Dexed 4.0 MB: 0.3-0.4 s x86_64, seconds on a Pi) under the lock main() takes before closing (exit-fixes), and jalv freed the LV2 world (~35 of ~40 ms of Helm's exit). Parse before the lock, quick exit (stop audio/worker/UI/plugin, `_exit()`), wake on the done semaphore instead of a 30 ms sleep, give up after 2 s with status 3 if the plugin hangs in run(). |
| [Helm](https://github.com/mtytel/helm) 927d2ed2 | open | — | **Endless loop in run().** Sometimes (3 in 60 rounds of 8 jalvs on one CPU, VM) `SynthBase::updateMemoryOutput()` spins in `while (memory_reset_period_ < window_length) memory_reset_period_ += memory_reset_period_;` with the engine's sample rate INT_MIN (period -inf): silent instance, a core busy, `jack_deactivate()` never returns. Cause of the bad sample rate not found yet (needs a debug build). |
| several (Helm, Dexed, TAL-NoiseMaker, multi-q-2, miniopl3, ZynAddSubFX LV2 preset banks) | proposed | recipes | **One big preset file.** lilv parses a preset's whole file when the first preset loads (1-6 MB here): one file per preset (manifest `rdfs:seeAlso` per preset) would make preset loads cheap in every host. |

## Portability (musl, current compilers)

| Project | Status | Where | Problem and fix |
|---|---|---|---|
| [LinuxSampler](https://www.linuxsampler.org/) 2.5.0 | sed | `aports/engines/linuxsampler/APKBUILD` | `configure`'s UNIX98 test fails on musl, which has `pthread_mutexattr_settype()` (`HAVE_UNIX98=1` needed); `execinfo.h` included unconditionally (`src/common/global_private.cpp`, backtraces for Mutex debug info only): stub header. |
| [DISTRHO-Ports](https://github.com/DISTRHO/DISTRHO-Ports) (JUCE 5) | sed | `aports/lv2/distrho-ports-lv2/APKBUILD` | `execinfo.h` and `backtrace()` unconditional in JUCE's core (`#if defined (__GLIBC__)` around them); `static_cast<char>(NULL)` in juced's OSC code (`NULL` is `nullptr` on musl). |
| JUCE plugins (CHOW, Surge's Monique, Dusk Audio, KR-106, RipplerX, Helm, Vaporizer2, ...) | sed | their recipes | The same in each bundled JUCE: `execinfo.h`, the glibc locale items `_NL_IDENTIFICATION_*`/`_NL_ADDRESS_*` in `getUserLanguage()`, `stat64` without `_LARGEFILE64_SOURCE`; older JUCE: `<utility>` for `std::exchange`. Upstream JUCE has some of it fixed: a plugin update to a current JUCE removes the need. |
| [Vaporizer2](https://github.com/VASTDynamics/Vaporizer2) | sed | `aports/lv2/vaporizer2-lv2/APKBUILD` | `arc4random()` used unless glibc < 2.36: musl has none (libbsd here). Check for the function, not the glibc version. |
| [Triceratops](https://github.com/thunderox/triceratops) | sed | `aports/lv2/triceratops-lv2/APKBUILD` | `(uint)` cast: `uint` is a glibc typedef. Fix: `unsigned int`. |
| [caps-lv2 (MOD)](https://github.com/moddevices/caps-lv2) | sed | `aports/lv2/mod-caps-lv2/APKBUILD` | glibc's internal `__intN_t` types in `basics.h`. Fix: the standard `<stdint.h>` types. |
| [hcs (Pd)](https://github.com/pd-externals/hcs) | sed | `aports/pd/pd-hcs/APKBUILD` | `stat.c` takes the BSD field names (`st_atimespec`) unless `_POSIX_C_SOURCE` is defined, which glibc defines implicitly and musl doesn't. Fix: the POSIX branch on Linux too. |
| [tap-lv2 (MOD)](https://github.com/moddevices/tap-lv2) | sed | `aports/lv2/mod-tap-lv2/APKBUILD` | `-Werror` in the build flags breaks with newer compilers' warnings. |
| [ChowMultiTool](https://github.com/Chowdhury-DSP/ChowMultiTool) | open | `aports/lv2/chow-multitool-lv2/APKBUILD` | GCC 15's LTO crashes on it (internal compiler error in `write_symbol`): built without JUCE's LTO flags. A GCC bug to report, with a reduced case. |
| [plugdata](https://github.com/plugdata-team/plugdata) (its Pd fork) | sed | `aports/lv2/plugdata/APKBUILD` | Pd plans its FFTs with `FFTW_MEASURE` (`src/d_fft_fftw.c`), which times candidate algorithms each time a plan is made: every plugin instance pays for it at start (and the LV2 helper at build time, very slow under QEMU). `FFTW_ESTIMATE` here; upstream could keep FFTW wisdom or use `FFTW_ESTIMATE` for plugin builds. |
| [plugdata](https://github.com/plugdata-team/plugdata) | open | `aports/lv2/plugdata/APKBUILD` | The `fuzzysearchdatabase` submodule is on Bitbucket (user URL `https://timschoen@bitbucket.org/...`); a GitHub mirror would make source archives easier. |
